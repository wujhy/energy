# 01document 文档入口

更新时间：2026-06-30

本文是 `01document` 的入口索引。后续接手优先看本文件和 `当前计划任务.md`，不要从归档计划里继续拆任务。

## 新会话必读边界

1. 默认只执行 `当前计划任务.md` 中“当前待办”下的功能主线任务；“交给其他 AI 的验证任务”“可分派低复杂度开发任务”只作为分派池，除非用户明确点名任务编号，否则不执行、不改完成状态。
2. 开始前先看 `git status --short`，区分已有改动和本轮改动；不得整理、回滚或提交非本轮目标文件，尤其不要处理 `.codegraph/`、数据库文件和其他 AI 正在改的测试文件。
3. 代码任务先用 `.codegraph` 了解调用面，再做小步修改；测试验证任务只做本轮功能必要的最小自检，不主动扩展其他 AI 的测试清单。
4. 修改文本文件优先用 `apply_patch`；如果工具在 Windows sandbox 下不可用，才允许使用 .NET `UTF8Encoding(false)` 精确写入，写后必须检查文件头并执行相关测试或 `git diff --check`。
5. Windows 下不要用中文正文作为唯一替换锚点；优先使用 ASCII 方法名、类名、import、任务编号等稳定片段，避免控制台乱码导致误改。

## 已归档计划

已完成、过期或已被当前主文档吸收的计划统一移动到：

归档文件只作历史追溯，不再作为新任务来源。需要恢复任务时，应先把结论合并到 `当前计划任务.md` 或对应主文档，而不是直接修改归档计划。

## 维护规则

1. 新任务优先写入 `当前计划任务.md`，长期背景再同步到 `蓄电池采集整合计划.md` 或 `energy_refactor_current_plan_20260622.md`。
2. 完成的任务从当前任务列表移到“近期已完成”，必要时只保留提交号和一句结果。
3. 不再新增零散计划文档；确需新增时先判断能否并入当前主文档或辅助参考。
4. 协议原件、图片、Word 方案和运行态数据库不参与计划归档。
