## 2. 设备上行数据流

```text
路径 A：新 600 节采集模块端协议

600节采集模块
  │ 串口帧：BatteryCollectorFrameCodec
  v
BatteryCollectorService
  │ - 每通道独立线程
  │ - 常态 01/81 轮询
  │ - 外部控制指令可在单条采集完成后插队
  v
BatteryModuleFrameDispatcher
  ├─ BatteryModuleFrameLogConsumer
  │    └─ battery_module_frame_log                       [协议日志]
  ├─ BatteryModuleRealtimeConsumer
  │    ├─ battery_module_realtime                        [新实时表]
  │    ├─ BatteryModuleGroupCalculationService           [组级汇总]
  │    ├─ BatteryModuleAlarmAdaptService                 [告警适配]
  │    └─ BatteryModuleCompatReportLogSyncService        [兼容旧历史]
  │         └─ dev_battery_report_log                    [旧页面/上报兼容]
  └─ BatteryModuleModbusReadMappingService               [待扩展：读映射]

下游读取
  ├─ BatteryReportLogService / StatBattery* / ScreenService
  ├─ AlarmLogService
  └─ DataReportJob -> ClientReportService -> 第三方平台
```

```text
路径 B：旧 CM03N / 旧设备通信

设备串口或 TCP
  ├─ SerialPortConfig / SerialPortHandler
  └─ TcpServerConfig / TcpServerHandler
       │
       v
DeviceService
  │
  v

  ├─ CM03N.DataUploadHandler
  ├─ CM03N.DevResponseHandler
  ├─ battery.BatteryPackHandler
  ├─ battery.BatteryParamsHandler
  ├─ battery.BatteryAlarmHandler
  └─ battery.BatteryOptResHandler

  ├─ dev_battery_report_log
```

标注：

- [待整合] 路径 A 和路径 B 都会影响 `dev_battery_report_log`、告警、统计，建议最终明确“新采集模块为主数据源，旧 IoT 作为兼容输入”。
- [待优化] `resources/dist` 为前端构建产物，不宜作为长期维护源码入口。
- [待扩展] `BatteryModuleModbusReadMappingService` 可作为后续 Modbus/第三方读点位映射层。

## 3. 控制指令流

```text
页面控制入口
  ├─ OptBatterySetController
  │    └─ ControlBatterySet
  │         ├─ manualModelNum       手动编号
  │         ├─ autoModelNum         自动编号
  │         ├─ resistance           设置内阻系数
  │         ├─ correct              校准参数
  │         └─ restore / delHost    本地恢复、清理
  │
  └─ BatteryCollectorCommandController
       ├─ /collector/battery/status
       ├─ /collector/battery/moduleAddressCache/reset
       ├─ /collector/battery/manualModuleAddress
       └─ /collector/battery/execute                 [980兼容映射入口]

ControlBatterySet / BatteryCollectorCommandController
  │
  v
BatteryCollectorCommandService
  ├─ 专用方法：直接构造 600 节模块端命令
  │    └─ BatteryModuleControlCommandService
  │         └─ BatteryDeviceProtocolCode              [600节采集模块端协议码]
  │
  └─ execute(BatteryAggregateCommandDefinition)       [兼容旧980聚合命令]
       ├─ 可映射：转换成 BatteryDeviceProtocolCode
       └─ 不可映射：unsupported，不直接下发
  │
  v
BatteryCollectorService.submitModuleCommand
  │
  v
通道队列 queuedModuleCommands
  │
  ├─ 常态采集中：当前采集帧完成后，外部指令优先执行
  └─ 空闲时：立即下发
  │
  v
600节采集模块串口
```

标注：

- [待整合] `BatteryAggregateCommandDefinition` 是 980 聚合协议语义；`BatteryDeviceProtocolCode` 是 600 节模块端协议语义。当前兼容映射可用，但命名容易误导。
- [待优化] 建议把 `execute(...)` 改名为 `executeAggregateCompat(...)`，业务路径优先走专用 600 模块端方法。
- [待优化] `BatteryCollectorCommandResult` 同时保存 980 定义和 600 模块命令，建议对业务返回突出 `moduleControlCommand.protocolCode`。
- [待扩展] 若后续存在真正 980 聚合设备，需要单独建立聚合设备通道，不应复用 600 模块串口下发。

## 4. 第三方平台交互流

```text
上报方向：energy -> 第三方平台

定时任务
  ├─ HeartbeatJob
  │    ├─ report.heartbeat
  │    └─ report.register
  │
  └─ DataReportJob
       ├─ 告警上报：AlarmLog -> ClientReportService.uploadAlarm
       ├─ 数据上报：ConfigHistoryVo -> uploadData
       ├─ 配置上报：Config / ConfigAttribute -> uploadDev / uploadAlarmConfigItem
       ├─ 操作记录：DevBatteryOpt -> uploadBatteryOpt
       ├─ 单体数据：DevBatteryMonomer -> uploadBatteryMonomer
       └─ 预测/核容：PreBatteryGroup -> uploadPreBatteryGroup

ClientReportService
  │
  v
TcpClient
  │ JSON RequestVo / ResponseVo
  v
第三方平台
```

```text
下发方向：第三方平台 -> energy

第三方平台
  │ TCP JSON
  v
TcpClientHandler
  │
  v
ClientDeviceService.readByTcp
  ├─ HostHandler       主机信息、时间同步、升级
  ├─ ConfigHandler     设备配置同步
  ├─ AttributeHandler  告警项同步
  ├─ AlarmHandler      告警同步
  └─ BatterySyncHandler
       ├─ syncBatteryOpt
       ├─ syncBatteryMonomer
       ├─ reportSynBatteryMonomer
       └─ 调用 BatteryCollectorCommandService / ControlBattery
```

标注：

- [待整合] 第三方命令下发到电池控制时，需要统一协议边界：第三方业务命令 -> 业务命令 -> 600 模块端命令。
- [待优化] 上报数据源应优先从新实时表/兼容历史表中明确选择，避免同一时刻新旧链路重复上报。
- [待扩展] 可增加上报队列、失败重试和幂等记录，降低 TCP 连接抖动对业务数据的影响。

## 5. 缓存与持久化

```text
配置类数据
  ├─ battery_pack

  ├─ alarm_level
  └─ dev_battery_opt

  ├─ battery_module_realtime
  ├─ battery_module_frame_log

  ├─ alarm_log
  ├─ stat_battery_pack / stat_battery_bat / stat_battery_res

```

标注：

- [已推进] 业务内部正在去除 `config_id` 作为多配置维度，保留数据库字段和外部兼容。
- [待优化] 缓存 key 已精简 `config_id`，需要继续关注前缀匹配边界，避免 `packNum=1` 命中 `packNum=10`。
- [待整合] 新采集模块实时表、旧历史表、统计表之间需要明确“主表、兼容表、派生表”的关系。

## 6. 定时任务与后台维护

```text
scheduled/*
  ├─ CacheJob          配置、告警、电池组缓存刷新
  ├─ DeviceOnlineJob   设备在线状态
  ├─ CleanLogJob       日志/历史清理
  ├─ ProjectJob        看门狗
  ├─ RestartAppJob     应用重启
  └─ SoundWarnJob      声光告警，当前调度疑似关闭

sync/scheduled/*
  ├─ HeartbeatJob      第三方心跳/注册
  └─ DataReportJob     第三方业务数据上报

collector/*
  └─ BatteryCollectorService
       └─ 非 @Scheduled：每通道常驻线程，自身按 pollIntervalMs 控制轮询
```

标注：

- [待优化] 采集线程不建议整体替换为 `@Scheduled`；可以只把轮询触发调度化，串口 IO 保持常驻。
- [待扩展] 定时任务建议补充统一运行状态、最近成功时间、失败原因和手工触发入口。

## 7. 当前优先级建议

```text
P0 协议边界
  ├─ 600 节模块端协议：BatteryDeviceProtocolCode
  ├─ 980 聚合兼容协议：BatteryAggregateCommandDefinition
  └─ 禁止 980 原始协议码直接下发 600 模块串口

P1 数据源整合
  ├─ 明确新采集模块实时表为主源
  ├─ dev_battery_report_log 作为旧页面/上报兼容层
  └─ 统计表作为派生结果

P2 缓存与 config_id 收口
  ├─ 内部服务按 packNum/modelNum/itemCode 访问
  ├─ DB 字段继续保留默认 config_id = 1
  └─ 清理残留 config_id 业务分支

P3 第三方同步可靠性
  ├─ 上报幂等
  ├─ 失败重试
  ├─ 命令下发审计
  └─ 新旧链路重复数据治理
```
